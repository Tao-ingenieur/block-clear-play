### 2. 产品与原创要求

- 类型：可离线游玩的方块下落消除游戏，休闲友好，同时保留可调的进阶手感。
- 显示名使用《方块消消看》，不采用第三方知名游戏名称、Logo、官方素材、音乐、音效或整体视觉表达。不宣传官方认证或当然取得知识产权许可。
- 网格、方块、标志、界面与动效自行设计；优先使用 Canvas/CSS 程序化绘制。音乐与音效采用原创 Web Audio 合成，不依赖未授权录音或采样。
- 优先用系统字体，不打包来源不明的字体。第三方代码、字体或素材必须记录来源、版本、许可证和署名要求，运行包保留必要许可文件。
- 工作名不代表已完成商标检索。正式发行前按目标市场确认品牌、游戏运营、隐私、未成年人保护及商业化要求，不能承诺“免费即不需要资质”。

### 4. 必须实现的规则契约

采用项目自定义版本化规则 echo-v1，不声称完整符合某个受保护产品的官方认证。接手现有仓库时以 docs/rules/echo-v1.md 和受测试保护的源码为准；行为变化影响回放时升级 ruleset，不悄悄修改。

#### 棋盘、随机与旋转

- 棋盘宽 10，总高 40；y=0…19 为隐藏区，y=20…39 为可见区。x 向右，y 向下。空格 null、垃圾 G，行数组不得共享引用。
- 七种四格块按 I、O、T、S、Z、J、L 排列。出生 frame 左上角 x=3、y=19，朝向 0。出生碰撞结束；锁定、清行、垃圾注入后，隐藏区仍有占用则结束。
- 7-Bag：每袋七种各一次，Fisher–Yates 洗牌，用拒绝采样消除取模偏差。整数 PRNG 为 `state=(Math.imul(state,1664525)+1013904223)>>>0`，seed 为 0…2^32−1。袋从尾部 pop。随机状态、袋及队列全部可序列化。
- 垃圾独立随机流初值 `(seed ^ 0x9e3779b9)>>>0`，不影响出块序列。PRNG 不是加密随机数。
- JLSTZ 使用 3×3 frame，I 使用 4×4 frame；顺时针坐标变换为 `(x,y)→(N−1−y,x)`。O 四个方向几何不变。出生坐标如下：

```text
I: (0,1) (1,1) (2,1) (3,1)
O: (1,0) (2,0) (1,1) (2,1)
T: (1,0) (0,1) (1,1) (2,1)
S: (1,0) (2,0) (0,1) (1,1)
Z: (0,0) (1,0) (1,1) (2,1)
J: (0,0) (0,1) (1,1) (2,1)
L: (2,0) (0,1) (1,1) (2,1)
```

90° 旋转使用 SRS，必须包含完整偏移表，按顺序取第一个合法结果。下表已转换到 y 向下坐标；0/1/2/3 分别是出生、右、倒、左朝向。O 只测试 (0,0)。不要混用 y 向上的表。

JLSTZ:

1→0: (0,0),(1,0),(1,1),(0,-2),(1,-2)
1→2: (0,0),(1,0),(1,1),(0,-2),(1,-2)

- 180° 是独立可选扩展：默认关闭、无踢墙、不产生 Spin 奖励，不冒充标准 SRS 的一部分。
- Hold 每次锁定前只能交换一次；取出块恢复出生朝向，锁定后恢复 Hold 权限。Ghost 由碰撞推导，不修改实际块。
- 显示五块预览。处理边墙、地板、隐藏区、出生阻塞和垃圾溢出。

#### 时间、输入与手感

- Core 固定 120 tick/s，requestAnimationFrame 仅驱动累积器与渲染，禁止把每次渲染当作一次逻辑步。
- 输入结构 `{tick,sequence,action,pressed}`。`step` 接收下一 tick 的合法输入批次，批内 sequence 严格递增；回放 sequence 全局递增。非法批次先整体拒绝，不允许部分修改状态。
- tick 内先按序执行输入，再执行自动重复、重力与锁定。同 tick 硬降后，新出生块可接受剩余操作；游戏结束后不再处理余下操作。
- 左右后按优先，释放当前方向时回到另一仍按住方向并重新等待 DAS；首次按下立即移动。忽略系统 keydown 重复。软降为按住状态，旋转/Hold/硬降为离散动作。

| 预设 | DAS tick | ARR tick | 锁延迟 tick | 软降倍率 |
|---|---:|---:|---:|---:|
| 新手 | 22 | 6 | 90 | 10 |
| 标准 | 18 | 3 | 60 | 20 |
| 硬核 | 12 | 0 | 36 | 40 |

- ARR=0 表示 DAS 后直接到可达边界。触地成功横移或非 O 旋转最多重置锁延迟 15 次，离地不恢复次数；失败动作和 O 原地旋转不得续锁。硬降立即锁定。
- 用整数微格累积重力：初始每秒 1,000,000 微格，一格为 1,000,000；升级速度按 floor(previous×3/2)，上限 2400 格/秒。每累计十行升级，上限等级 40；当前消行使用升级前等级计分。
- Master 为 1200 格/秒，即每 tick 十格，对应传统 60Hz 下的 20G；不要误写为每 tick 二十格。锁延迟 36 tick。
- 成功 90° 旋转记录踢墙序号；失败旋转保留旧记录。实际平移或下降清除记录，零距离硬降保留记录。
- 暂停和失焦先消费尚未处理的输入并记录方向释放，再暂停，避免“硬降后立即暂停导致操作丢失”。恢复后不补算后台经过时间。

#### Spin、得分、垃圾与双人逻辑

T 块锁定时，最后有效动作记录为旋转且中心四角至少三角被墙或格占用才进入 Spin 判定。朝向前侧两角都占用为 Full，否则为 Mini；90° 最后一个踢墙测试成功可升级 Full。前角随朝向旋转。

| 消行数 | 普通分 | Full Spin 分 | Mini 分 | 普通攻击 | Full 攻击 | Mini 攻击 |
|---:|---:|---:|---:|---:|---:|---:|
| 0 | 0 | 400 | 100 | 0 | 0 | 0 |
| 1 | 100 | 800 | 200 | 0 | 2 | 0 |
| 2 | 300 | 1200 | 400 | 1 | 4 | 1 |
| 3 | 500 | 1600 | 不适用 | 2 | 6 | 不适用 |
| 4 | 800 | 不适用 | 不适用 | 4 | 不适用 | 不适用 |

- 基础分乘等级；软降每实际格 +1，硬降每实际格 +2，不乘等级、不重复累计。
- 首次连续消行 Combo=0，此后递增，附加 `50×Combo×等级`；未消行锁定重置为 −1。
- 四行与 Spin 消行属于困难消行。连续困难消行从第二次起基础分×1.5；普通消行打断，无消行保留 B2B。其他奖励不参与该倍率。
- 全清按整个四十行棋盘为空判定，消 1/2/3/4 行分别另加 800/1200/1800/2000×等级，不设额外 B2B 全清特例。
- B2B 困难攻击 +1；Combo 为 0–1/2–3/4–5/6–7/≥8 时攻击分别 +0/1/2/3/4；全清攻击再 +10。零消行不攻击。
- 锁定先抵消已到达的待注入垃圾，余量发送；非消行锁定才注入剩余垃圾，每次最多八行。垃圾按 due tick、sequence 排序，逐行随机洞，溢出结束。
- 纯逻辑双人模拟同一 tick 同时结算双方、再判胜负和投递攻击，攻击延迟 60 tick，不能让先遍历的一方得到优势。尚未实现网络连接时，只把它称为双人结算模块。
- 纯连接状态机含 idle/connecting/handshake/ready/backoff/closed，重试 500/1000/2000/4000/8000ms，握手成功重置，不兼容协议或 ruleset 关闭。
- 在线输入门禁：每批≤64、每 tick≤8、sequence 递增、允许 serverTick−60 到 serverTick+6 且 tick≥1；标准竞技拒绝 180°。门禁不等于服务器重算或完整反作弊。

#### 六种单人模式与持久化

- Marathon：无尽，累计十行升级。
- Sprint：达到或超过四十行获胜，记录有效模拟时间。
- Ultra：120 秒积分；tick=14400 时先结束，再处理输入。
- Master：20G，达到或超过二百行获胜。
- Blitz：120 秒，每 1800 tick 提升等级，上限十级。
- Puzzle：无自动重力和自动锁定；固定棋盘、队列、目标与块数预算，硬降确认。提供二十个原创教学残局和可执行解法：十个单列四行洞、九个相邻两列双行洞、一个底行四格横洞。
- 设置、记录和单局存档分开；记录按模式与影响规则的配置隔离。
- 快照与回放带 schema、ruleset。保存 Config、seed、完整随机状态、按键状态、锁定计时、队列与垃圾；回放保存初始配置、输入 tick/sequence、endTick。
- 恢复时验证数据类型、矩阵尺寸、范围及状态一致性，拒绝损坏和不兼容数据。哈希只用于诊断，不能作为防作弊或签名。
- 提供回放导入、导出、播放；播放必须由输入驱动同一个 Core，不能直接播放录制画面代替规则重算。

### 5. Web 完整闭环与视听

- 使用 Canvas 2D 绘制棋盘和预览，DOM/CSS 提供菜单、信息、设置与反馈。根据 devicePixelRatio 设置绘图缓冲区，避免高 DPI 模糊。
- 视觉为原创安静的深色设计：背景参考 #11191c，柔和薄荷绿强调色参考 #b2d6bf。桌面可采用左侧模式导航、中间棋盘、右侧成绩/预览布局；手机优先棋盘、紧凑统计和底部触控，不能把桌面三栏生硬缩小。
- 完整展示分数、行数、等级、计时、Combo、B2B、Spin/全清反馈；含开始、暂停、继续、重开、结算、设置、帮助、残局选择与进度恢复。
- 至少深色、浅色、高对比三主题，色弱符号、较大字号、减少动态效果和明确焦点态。不要用高频闪屏表达奖励。
- 中文/英文全部使用语言表，切换即时生效。虚拟按键、帮助及键位说明保持一致。
- 默认键盘：左右箭头移动，↓软降，Space 硬降，↑顺时针，Z 逆时针，C Hold，A 可选 180°，Esc 暂停；允许重映射并校验冲突。
- 触控支持虚拟按键、轻点旋转、水平滑动移动、下滑硬降，手势可关闭。处理 pointercancel、失焦和多点触控，不留下卡住的按键。
- 三组原创合成循环旋律及旋转/硬降/消行/Spin/Combo/全清/结束音效，音乐/音效音量分离，一键静音。音频由用户交互解锁，不能假设移动平台自动播放成功。
- 适配安全区、横竖屏和低高度视口。至少检查 360×640、390×844、844×390、1440×960，确保棋盘及必要操作可达。
- 不依赖外部 CDN、字体、音频或素材请求；资源离线可用。
- **生产包必须双击 index.html 即可运行。** Vite 生产构建使用经典 IIFE 普通脚本，输出 index.html、game.js、game.css 与相对引用；不要要求玩家启动开发服务器来弥补 file:// 模块加载失败。开发入口仍可使用模块。
- Web 同时支持 HTTP/HTTPS 静态部署。本地文件存储受浏览器策略限制，失败时仍可开始游戏并给出简洁反馈。不要把 Electron Chromium 自检说成所有浏览器都已测试。

### 6. Windows：只交付绿色版

- Electron + electron-builder 的 dir 目标，x64；仅交付 `dist/windows/BlockClearPlay.exe` 及其完整依赖目录，不生成 NSIS 安装器，不生成 Setup EXE，也不把单个 EXE 冒充独立单文件产品。
- Web 资源放入 resources/web，应用代码使用 asar。先在忽略的构建缓存中生成并校验新程序，成功后整体替换 dist/windows，删除旧 EXE、旧 DLL 和旧资源，失败时保留旧成品。
- EXE 和目录名不含版本号；版本来自 package.json，保留在 EXE 元数据和 version.json。存档位于用户 AppData，构建替换不得删除个人进度。
- 使用安全的本地自定义来源，例如 echo://game，不启动对外监听的 HTTP 服务。限制路径越界、任意导航、新窗口与不必要权限。
- renderer 使用 contextIsolation、sandbox、nodeIntegration=false，不暴露 Node 全局能力。不隐式使用用户签名密钥；未签名时如实标记为开发版。
- 原创 ICO 图标可由脚本生成。保留 Electron/Chromium 所需许可证和通知。
- 告诉玩家必须复制整个 windows 目录。DLL、pak、locales、resources、snapshot 等不是可随便删除的中间文件。

### 7. Android：由 GitHub Actions 生成真实 Debug APK

- 使用 Java Activity + Android System WebView，复用已构建的 Web 资源和同一个 Core，不再重写玩法。
- 参考工具链：JDK 17、Gradle 8.11.1、AGP 8.9.2、compileSdk/targetSdk 35、Build Tools 35.0.0、minSdk 26、AndroidX WebKit 1.12.1。升级时按官方兼容矩阵调整。
- applicationId 基础值 io.dropgrid.blockclearplay，Debug 可加 .debug；versionName 与 package.json 同源，versionCode 有明确递增方案。
- 用 WebViewAssetLoader 的本地 HTTPS 来源加载打包资源，例如 https://appassets.androidplatform.net/assets/web/index.html；开启 JavaScript 和 DOM 存储，禁用不必要 file:// 访问，阻止任意外部导航。不添加当前离线功能不需要的联网/存储权限。
- 处理系统栏/刘海安全区域、横竖屏、切后台暂停和存档。使用系统文档选择器导入回放；通过仅允许可信来源及主 frame 的 WebMessageListener 导出 JSON，限制大小与数据格式，不能暴露通用高权限 JS 桥。
- 每次构建前同步当前 Web 生产资源，缺失时失败，不打包旧文件或空壳。
- 工作流支持主分支相关代码 push 自动触发和 workflow_dispatch 手动触发，最小 contents:read 权限，同分支旧构建可取消。
- 流程：checkout → Node/pnpm → JDK/Android SDK/Gradle → 冻结锁文件安装 → `pnpm verify` → `assembleDebug lintDebug` → 产物整理 → apksigner verify → APK 内资源检查 → upload-artifact。
- SDK 安装明确指定所需包；不要沿用安装已移除 tools 包的默认配置。参考已验证 setup-android 配置为 packages: platform-tools，再安装 SDK 35 和 Build Tools 35.0.0。
- GitHub Artifact 上传使用已经解析的绝对产物路径；例如打包脚本写 GITHUB_ENV 的 ANDROID_APK_OUTPUT，再交给 upload-artifact。不要直接提交包含 `../` 的上传路径模式。
- Artifact 名称 android-debug，内含 BlockClearPlay-debug.apk、version.json、SHA256SUMS.txt、README.txt，参考保留期十四天；单独保存 lint 报告。工作流失败要看日志并修复，不停在“已写好 YAML”。
- 本地下载至固定 `dist/android`，成功校验后替换旧包，不保留重复下载 ZIP/解压副本。比对 SHA-256、Manifest/DEX 存在，以及打包 Web 资源与本地生产构建一致。
- Debug 可侧载测试但不能作为商店发行包。临时云端 Debug 密钥可能变化，覆盖安装可能失败；需要卸载时明确说明会删除存档。正式发行另行配置稳定的发布签名与 AAB，密钥不进入仓库。

### 8. 构建、目录和清理约定

提供以下用途明确的命令，README 给出前置环境、执行位置与产物入口：

```text
pnpm install --frozen-lockfile
pnpm dev:web
pnpm typecheck
pnpm test:coverage
pnpm build:core
pnpm build:web
pnpm build
pnpm verify:build
pnpm verify
pnpm build:windows
pnpm smoke:windows
pnpm build:android
pnpm clean:cache
```

- repo 只保存源码、配置、锁文件、测试及必要文档，dist 只保存生成产物。不得生成 dist/source、源码复制目录、重复源码 ZIP 或重复 Web ZIP。
- 目录固定，不用 web-v0.1.0、windows-v0.1.0 等命名。版本保留在软件与清单中，新成品生成成功后清除旧程序及过时资源。
- dist/core 是开发用 JS 规则库，不是独立游戏，要在说明中写清。每个平台目录均提供简短运行说明和校验/版本信息。
- Git 排除 node_modules、dist、.cache、.vite、.gradle、build、coverage、日志、本地 SDK 路径与密钥；不能误忽略需要提交的源码。
- clean:cache 使用固定白名单清理下载副本、自检 profiles、Vite/Gradle/Android build 缓存；保留已装依赖、当前 dist、源码、测试、许可证、正式用户存档。
- 清理/递归删除/移动前校验解析后的绝对路径和 realpath，拒绝越出工程及目录重定向，不遍历并删除用户全局依赖缓存。清理可重复执行，第二次没有残留时正常成功。
- 清理成品无关缓存后，用哈希确认 EXE、APK、Web 及必要 Core 产物未被修改。不要凭文件扩展名批量删掉 Windows 运行依赖。

### 9. 验收与交付证据

#### Core

- 使用真正断言的自动测试覆盖七袋、全部旋转转换及 I/O 特例、边墙/地板、碰撞与出生、Hold/Ghost、DAS/ARR、锁延迟、Spin/Mini、计分、Combo/B2B/全清、垃圾、模式结束、非法输入及损坏存档。
- Core 行、分支、函数覆盖目标均为 100%；不加 coverage ignore 掩盖缺口，不写空测试凑覆盖率。现有基线是 42 项测试，新实现不必机械保持测试数量。
- 使用多 seed 的状态不变量与快照恢复后继续模拟测试；编译后的 Core 与源码重放同一输入，状态及事件应一致。二十个残局均有机器可执行解法。
- 接手现有源码时保留 `tests/fixtures/seed-17.json` 的黄金回放：tick=500、score=36、hash=7f3279ab。若完全从零实现并采用不同状态序列化格式，应独立建立经过测试验证的黄金向量，不强行伪造该哈希，也不声称与现有格式兼容。

#### Web 和 Windows

- 对实际生产包检查启动、六模式、触控及布局、暂停/重开、设置、存档恢复和回放，不只验证开发服务器首页。
- 对最终打包的真实 EXE 做隐藏窗口自检，分别检查正常本地协议入口与 file:// Web 入口。
- 自检至少包含：页面与 renderer 成功加载、没有 Node 全局暴露、通过真实 UI 解开第一个竖列残局、暂停不丢输入、存档刷新后可恢复、没有 renderer error。现有兼容实现第一关为旋转 I、左移五次、硬降，清四行得 2834 分。
- 截图来自实际运行页面，自检临时用户目录隔离，不能覆盖正式玩家存档。保留必要报告，其余可通过 clean:cache 清除。
- 不能把目标“稳定 60fps、冷启动小于三秒”等写成测量结果。性能报告需设备、系统、构建、场景和测量方式；没有测量就标未测。

#### Android 和交付说明

- 必须有成功的 GitHub Actions 运行链接、真实 APK、签名检查、资源检查、下载哈希以及对应源码提交。构建成功不能写成真机测试已通过。
- 可用设备/模拟器时验证安装、离线启动、触控、安全区、横竖屏、音频、切后台恢复、回放读写；无环境则明确未测。
- 最终交付清单列出可点击的本地入口、GitHub 地址、构建运行方法、已完成与未完成平台、已知限制。GitHub 上传源码；二进制使用 Actions Artifact 或经用户授权的发行渠道。
- 当前基线验收应包含 Web 可玩包、Windows 绿色版、Android Debug APK、源码、规则文档、授权台账、平台说明及测试报告。没有生成某平台产物就明确说明，不能用“TypeScript 可复用”代替实际适配。

### 10. 后续五平台与商业化扩展（仅在用户要求时执行）

1. 微信优先小游戏形态：复用 Core，单独适配 wx Canvas、触控、音频、存储、生命周期、分包与平台接口；不能把 DOM Web 页面直接当小游戏包。交付开发者工具可导入工程与实际验证记录，AppID、资质和审核按用户实际账号处理。若要求小程序，先说明与小游戏差异并按指定形态实现。
